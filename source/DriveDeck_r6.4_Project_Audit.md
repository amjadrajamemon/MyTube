# DriveDeck Pro r6.4 — project audit

**Audited archive:** `DriveDeck-Pro-r6.4-native-player-pip-search-safe-area-buildfix(1).zip`

## Executive assessment

The archive is an Android Studio **source project**, not a finished, portable APK or a Windows portal. Its player and browser contain substantial implementation, but its advertised download and playlist features are simulations. A successful Android build would not turn them into real downloads. The largest release blockers are the fake download/vault path, fabricated playlist contents, queue races, and an unverified build configuration.

This is a source audit, not a device certification. I checked the complete archive structure, Kotlin application paths, Android manifest/resources, Gradle files, Windows build script, and project documentation. ZIP integrity passed; all seven Android XML files parsed; the archive contains 17 Kotlin source files, no test source files, and no APK. `./gradlew --offline :app:assembleDebug` stopped before configuration because Gradle 9.0.0 is not cached and this workspace cannot reach `services.gradle.org`. There is no Android SDK or emulator here. **Compilation, playback on actual devices, and visual alignment remain unverified.**

Severity: **Critical** means a central promised feature cannot deliver its stated result; **High** means a likely functional, privacy, or reliability defect; **Medium** means an important mismatch or device dependent defect; **Low** means cleanup/documentation.

### Additional smaller defects and cleanup

- `TubeDeckRepository.kt:109–115` treats any occurrence of `v=` or `/shorts/` on **any domain** as a YouTube video ID. Validate host, path, and ID before native handoff; direct media URLs with a `v=` query can otherwise be misclassified.
- `DownloadModal.kt:53,176–181` always passes `MP4` even if audio mode is selected. The advertised MP3/M4A/OPUS output choices are absent. This is secondary to F01: no format conversion or actual file output exists.
- `DownloadsScreen.kt:278–295` accepts `onRetry` but never displays a Retry action; non-downloading rows always show Resume. The queue screen also displays progress without a distinct failed/paused/completed presentation.
- `TubeDeckRepository.kt:302–305` deletes only vault metadata. Once real files exist, this action should also remove the selected file with appropriate confirmation and error handling.
- `AndroidManifest.xml:6` requests notification permission, but there is no notification/channel/runtime request or foreground download service in the project.
- `app/src/main/res/layout/view_tubedeck_player.xml` is unused; `PlayerScreen.kt:321–325` creates `PlayerView` in code. The 5.8 MB bundled sample video exists chiefly to make simulated vault records appear playable.

## Visual and interaction review

The source shows two likely alignment problems: stacked scaffold/system insets (F13) and FAB positions with no upper bound (F14). A smaller portrait phone may also clip the `DownloadModal.kt:66–189` fixed height dialog content, and the six unscrollable quality chips in `PlayerScreen.kt:497–510` may overflow narrow dialogs. These are **device test candidates**, not screenshot verified defects. Test at small and large font sizes, portrait and landscape, gesture and 3 button navigation, display cutouts, and IME open/closed.

## Recommended sequence

1. **Make the app honest and usable:** replace simulated downloads/playlists (F01–F02), remove misleading progress/format labels until implemented, and verify saved files play offline with network disabled.
2. **Stabilize work:** serialize queue state, persist jobs, and make cancel/resume reliable (F03–F04).
3. **Fix playback and navigation:** align native/web policy, quality behavior, PiP setting, sponsor requests, link handling, and browser state (F05, F08–F11).
4. **Harden browser and settings:** constrain the bridge/HTTP exposure and ensure each toggle/metric reflects real behavior (F06–F07).
5. **Validate release:** align AGP/API/Gradle, build and install debug and signed release APKs, inspect layouts on devices, add a small regression suite, and update the package documentation (F12–F18).
